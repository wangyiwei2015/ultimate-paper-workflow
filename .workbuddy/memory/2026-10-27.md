## "刚装好却探测不到"：PATH 只对新进程生效
- 根因：安装器（winget/choco）只把 bin 目录写进 PATH，而**已运行的终端进程
  不会刷新环境块**，所以 `where latexmk` 失败 → 误判未安装 → 重复安装。
- windows.bat 修复：`:pick` 增加 PROBE_FUNC；`:probe_any` 有 PROBE_FUNC 时改调
  定位子程序 `:latex_present` / `:typst_present` / `:make_present`，翻常见安装目录
  （C:\texlive\<年>\bin\{windows,win32} 用 `for /d` 通配、MiKTeX、winget Links、
  GnuWin32、chocolatey\bin）。命中且不在 PATH 时置 FOUND_DIR，
  `:do_report`/`:do_install` 报 "[OK] (at <dir>) not on PATH"、临时 `set PATH=%PATH%;%FOUND_DIR%`、
  并累计到 NOT_ON_PATH 供结尾汇总；**不会重复安装**。
- Makefile 同步：TEX_INSTALL_DIRS / TYPST_INSTALL_DIRS / MAKE_INSTALL_DIRS 常量 +
  check-env 新增 "Toolchain folders found on disk" 段；`figs`/`paper` recipe 内
  用 `for d in ...; do if [ -x ... ]; then PATH="$$d:$$PATH"; export PATH; break; fi; done;`
  兜底（必须和命令同一逻辑行，否则跨行不继承）。
- 可移植性教训：**不要用 `$(shell ...)` 和 `$(subst ,, )` 空格技巧**——BSD/macOS make
  不保证支持；改成正则 sh 写在 recipe 里。同理 `%PROGRAMFILES(X86)%` 含括号，
  不要放进 `for ... in (...)` 列表，改用普通 `if exist`。

## 严重坑：.bat 必须是 CRLF，否则 cmd 报"找不到批标签"
- 现象：`The system cannot find the batch label specified - ext`，四个 `call :ext` 全挂，
  而文件中前段的标签（:pick/:pass/:probe_* 等）都正常——因为 Write/Edit 工具写出的是
  LF-only 文件，cmd 解析器标签偏移漂移，只在中后段炸。
- 修复：`awk '{printf "%s\r\n",$0}' windows.bat > t && mv t windows.bat`（CR=LF=543 已验证）。
  **每次用 Edit 改过 windows.bat 后都要重转一次 CRLF**（Edit 会把新行写成 LF）。
- 新增 `.gitattributes` 按扩展名强制：`*.bat/*.cmd/*.ps1 → eol=crlf`，
  `*.sh/Makefile/*.tex/*.typ/*.bib/*.m/*.md → eol=lf`，防止 git 检出时改回去。
- 排查方法坑：Git Bash 的 `sed`/`awk` 过管道会**吞掉 CR**，用它们 + `od` 会误判成 LF；
  要用 `cat file | od -c` 或 `dd bs=1 skip=<grep -abo 偏移> count=N | od -c` 直接看字节。
- 顺手把 `call :ext` 的参数里的括号去掉（"Makefile Tools - Microsoft official"），
  排除 call 带括号参数的残余风险。
- 收尾验证（2026-10-27）：Makefile CR=0/LF=232（Edit 未再次改坏）；windows.bat CR=LF=543、
  elevate.ps1 CR=LF=53、macos.sh LF=184，行尾全部符合 .gitattributes。
  已加 `make eol-check` 目标做守卫（.bat/.ps1 必须 CRLF、其余必须 LF，违反则 exit 1），
  正/负两条路径均用 sh 模拟实测通过（好→exit 0，坏→exit 1）。
  标签交叉校验：windows.bat 全部 goto/call 目标（含 if 块内联）均有对应 `:label`，
  唯一例外是 cmd 内建 `:eof`，属正常。elevate.ps1 已过 Parser::ParseFile。
  沙箱无 make/typst/pdflatex，无法实机编译，只能静态审阅 + 行尾/标签校验。

## 修复 `make matlab` 的 "find toolchain sh file not found" + TeX 包清单补全

### 根因：相对路径 + shell `cd`
- 用户报：macOS 上 `make check-env` 全 OK，但 `make matlab` 报
  `sh: setup/find_toolchain.sh: No such file or directory`。
- 原因是 recipe 写成 `@cd $(MATLAB_DIR) && $(FIND_TOOL) ...`：`FIND_TOOL` 是
  **相对路径**，shell 先 `cd matlab` 之后就解析成 `matlab/setup/find_toolchain.sh`。
  `check-env`/`figs`/`paper` 从不 `cd`，所以只有 `matlab` 目标炸。
- 修法：不 `cd`，改用 MATLAB 自己的 `-sd <folder>` 启动参数：
  `@$(FIND_TOOL) $(MATLAB_BIN) -sd $(MATLAB_DIR) -batch "$(MATLAB_ENTRY)"`。
  在 `FIND_TOOL` 定义处和 `figs` pattern rule 处都加了 INVARIANT/NB 注释。
- 用假 matlab 实测：`FAKE matlab invoked with args: -sd matlab -batch build_all_figs`，
  cwd = 仓库根，exit 0。

### 关键教训：BibTeX 没有注释语法（踩了两次）
1. `refs.bib` 里 `% @inproceedings{key2023,` 这种"注释掉"的模板，BibTeX **照样当条目解析**，
   `.blg` 报 `You're missing a field name`。
2. 改用 `@comment{...}` 包起来也不行——**BibTeX 的 @comment 只跳到下一个 `@`**，
   里面的条目仍然入数据库。所以 `\nocite{*}` 时 `key2023`/`key2020` 真的进了 `.bbl`。
3. 连 `%` 注释行里的 `@` 都危险：`%  no @string macros` 会报
   `I was expecting a '{' or a '('`；`% Copy it out of the @comment block` 会报
   `' just comes after an entry type`。
4. **结论**：`refs.bib` 里零 `@` 注释、零注释条目；条目模板移到 **agent.md §4.4**，
   `.bib` 只留活条目 + 一句指路。校验口诀：先 `bibtex` 看 `.blg` 0 error 再跑 latexmk。
- 另：`\nocite{*}` + 模板留在 .bib = 参考文献里会出现 `key2023`/`key2020` 假条目，
  这是发现上述问题的直接证据（`.bbl` 数出 4 条）。

### `make paper` 支持指定源文件：`SRC=`
- 用法：`make paper`（默认 `latex_paper/main.tex`）/ `make paper SRC=example_apl`
  / `SRC=example_apl.tex` / `SRC=latex_paper/x.tex`（任意路径原样用）。
- 解析放在 **recipe 里的 POSIX sh**（不用 GNU-only 的 `$(wildcard)`/`$(if)`）：
  `case` 补 `.tex` → 当前目录不存在则试 `$(PAPER_DIR)/` → 仍不存在就列出
  `latex_paper/*.tex` 并 exit 1。整块在同一个 shell 里，`$$t` 才活得到 latexmk 那一步，
  且 `FIND_TOOL` 是相对路径、必须在任何 chdir 之前展开（延续既有 INVARIANT）。
- **重大坑：变量不能叫 `TEX`。** `TEX` 是 **GNU make 内建变量，默认值 `tex`**
  （TeX 二进制名），它永远已定义，所以 `TEX ?= ...` 永不生效 → 不带参数时去找
  `tex.tex`，报 `no such file 'tex.tex'`。`LATEX` 同理（默认 `latex`）。
  改用 `SRC`（无内建冲突）。这条已写进 Makefile 注释 + agent.md §5 的引用块。
